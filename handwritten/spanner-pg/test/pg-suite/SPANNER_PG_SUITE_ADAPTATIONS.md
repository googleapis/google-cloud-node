# Cloud Spanner PG Suite Adaptations & Invariants

This document outlines the architectural adaptations, SQL dialect modifications, and feature exclusions applied to the standard `node-postgres` (`pg-suite`) integration test suite to run seamlessly against Google Cloud Spanner via `@google-cloud/spanner-pg`.

---

## 1. Architectural & Schema Adaptation Principles

### Primary Keys & Permanent `CREATE TABLE`
* **Upstream `node-postgres`**: Used `CREATE TEMP TABLE tableName(...)` or `CREATE TEMPORARY TABLE`.
* **Cloud Spanner Requirement**: Cloud Spanner does not support temporary or unlogged tables.
* **Adaptation**: Converted to standard `CREATE TABLE IF NOT EXISTS` with a Spanner-compatible Bit-Reversed identity primary key:
  ```sql
  CREATE TABLE IF NOT EXISTS tableName (
    spanner_pk_id BIGINT GENERATED BY DEFAULT AS IDENTITY (BIT_REVERSED_POSITIVE) PRIMARY KEY,
    -- additional columns
  )
  ```

### Asynchronous DDL Callback Chaining (`CREATE TABLE` -> `DML`)
* **Upstream `node-postgres`**: Issued unchained queries sequentially (`client.query('CREATE TABLE...')`, `client.query('INSERT...')`) over a single FIFO TCP socket connection.
* **Cloud Spanner Requirement**: Cloud Spanner processes DDL (`CREATE TABLE`) via the **Database Admin API** (`UpdateDatabaseDdl`) and DML/DQL (`INSERT`/`SELECT`) via the **Data API** (`ExecuteSql`). Schema changes take ~5-10s to propagate across Cloud Spanner database nodes on GCP.
* **Adaptation**: Chained callbacks so `CREATE TABLE` finishes on GCP before `INSERT`/`SELECT` queries are issued (`client.query('CREATE TABLE...', (err) => { client.query('INSERT...', ...); })`).

### Self-Contained Test Data Cleanup (`DELETE FROM`)
* **Upstream `node-postgres`**: Relied on temporary tables dropping automatically when TCP socket connections closed.
* **Adaptation**: Added explicit data cleanup (`DELETE FROM tableName`) before inserting test rows to prevent row accumulation across test runs.

### C. Dynamic Test Database Lifecycle & Executable Resolution

The test suite runner (`test/pg-suite-helper/run_pg_suite.cjs`) manages a clean database lifecycle:
1. **Fresh Database Creation**: Each full run creates a fresh temporary Cloud Spanner PostgreSQL database (e.g. `test-pg-<timestamp>-<rand>`).
2. **Post-Creation Warmup Delay**: Pauses 3 seconds (`await new Promise(r => setTimeout(r, 3000));`) after GCP database creation LRO to ensure Spanner database nodes and gRPC session channels warm up before tests run.
3. **Explicit Node Binary Resolution**: Executes child test processes using `process.execPath` (`/Users/gargsurbhi/.asdf/installs/nodejs/22.17.1/bin/node`) and `stdio: 'pipe'` to ensure execution reliability across subshells.
4. **Structured Test Logging & Cleanup**: Saves execution output to `testresults` and updates `test/test_results.json`. Deletes the temporary database automatically upon completion.

## 3. Core Driver Implementation Invariants

### `SpannerPool` DSN Caching & Fast Connection
* **DSN Pool Reuse**: `Client.connect()` caches `SpannerPool` handles per DSN string in a top-level `poolCache`. Re-connecting to the same Cloud Spanner database reuses active gRPC channels in **0ms**, eliminating connection churn and gRPC channel creation latency (~3s).

### Non-Blocking Connection & Iterator Teardown
* **Non-Blocking `doClose()` & `rows.close()`**: Cleared handle references immediately upon client/connection shutdown and dispatched `conn.close()`, `pool.close()`, and `rows.close()` asynchronously in the background (`void conn.close().catch(() => {})`). This prevents Node.js event loop blocking during CGO gRPC stream teardown.

### DSN Resolution & Database Name Fallback (`config.ts`)
* **Explicit `cfg.database` Preservation**: Preserves user-specified `cfg.database` parameters (e.g. `non_existent_db_12345`), falling back to `DATABASE_URL` target database only when `cfg.database` is undefined or set to the default `node-postgres` fallback string `'postgres'`.

### Global & Client Custom Type Parser Precedence (`types.ts` & `client.ts`)
* Implements per-client `TypeParserRegistry` inheritance (`this.types = new TypeParserRegistry(globalRegistry)`).
* Resolves custom type parsers according to priority order:
  1. `query.types` *(Query-level override)*
  2. `client.types` *(Client-instance override set via `client.setTypeParser`)*
  3. `client.config.types` *(Client constructor config)*
  4. `types` *(Global `pg.types`)*

### Transaction Status (`txStatus`) Tracking
* **`'I'` (Idle)**: Default state outside transaction blocks.
* **`'T'` (In Transaction)**: Set when `BEGIN` / `START TRANSACTION` starts execution.
* **`'E'` (In Error Block)**: Set when any statement inside an active transaction block fails. Resets to `'I'` when `COMMIT` or `ROLLBACK` completes execution.
