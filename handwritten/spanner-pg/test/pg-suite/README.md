# `node-postgres` (`pg-suite`) Integration Test Helper & Runner

This folder contains the dedicated test runner and helper utilities for executing the official `node-postgres` (`pg`) integration test suite (`test/pg-suite/integration/client/*-tests.cjs`) against a live **Google Cloud Spanner PostgreSQL-dialect database** using `spanner-pg`.

---

## 1. How to Execute the Tests

### Option A: Run the Entire Integration Suite
Run all integration test files against your target Spanner PostgreSQL instance:

```bash
DATABASE_URL="projects/span-cloud-testing/instances/<instance-id>/databases/<database-id>" \
  npm run test:pg-suite
```

Or directly via `node`:
```bash
DATABASE_URL="projects/span-cloud-testing/instances/<instance-id>/databases/<database-id>" \
  node test/pg-suite-helper/run_pg_suite.cjs
```

### Option B: Run a Specific Test File
You can filter execution by passing a filename or substring as an argument:

```bash
DATABASE_URL="projects/span-cloud-testing/instances/<instance-id>/databases/<database-id>" \
  npm run test:pg-suite array-tests.cjs
```
```bash
DATABASE_URL="projects/span-cloud-testing/instances/<instance-id>/databases/<database-id>" \
  npm run test:pg-suite transaction-tests.cjs
```

## 2. Automated Lifecycle of the Test Runner (`run_pg_suite.cjs`)

When you run `run_pg_suite.cjs`, it automatically performs a **3-step lifecycle**:

1. **Step 1: Table Preparation (`prepare_tables.cjs`)**:
   * Scans all test files in `test/pg-suite/integration/client/`.
   * Transforms SQL DDL syntax to be Spanner PostgreSQL compatible.
   * Pre-creates and clears all required test tables on your target Cloud Spanner database so tests do not fail on asynchronous DDL race conditions.
   * Records created tables in `test/pg-suite-helper/created_tables.json`.

2. **Step 2: Test Execution**:
   * Launches each test file in a dedicated child process with `PGDATABASE` and `TEST_TIMEOUT=30000` configured.
   * Streams live progress and collects pass/fail metrics.

3. **Step 3: Guaranteed Cleanup (`cleanup_tables.cjs`)**:
   * Whether tests pass or fail, the `finally` block executes `cleanup_tables.cjs` to drop all test tables tracked in `created_tables.json`, leaving your Cloud Spanner database 100% clean.

## 3. Transformations Made to Make `pg-suite` Work with Cloud Spanner PostgreSQL

Cloud Spanner's PostgreSQL dialect has architectural differences from standard local PostgreSQL. The following transformations are automatically applied by the `pg-suite-helper` scripts to adapt the official tests:

### A. `CREATE TEMP TABLE` -> `CREATE TABLE IF NOT EXISTS`
* **Why**: Cloud Spanner PostgreSQL does not support temporary or unlogged tables (`QTEMP/TEMPORARY or UNLOGGED objects are not supported in <CREATE TABLE> statement.`).
* **Change**: All occurrences of `CREATE TEMP TABLE <table>` or `CREATE TEMPORARY TABLE <table>` across the test suite are transformed to `CREATE TABLE IF NOT EXISTS <table>`.

### B. Synthetic Identity Primary Keys (`spanner_pk_id`) & `SERIAL` Transformation
* **Why**:
  1. Every persistent table created in Cloud Spanner requires a primary key (`Table <table> must have a primary key`).
  2. Spanner PostgreSQL does not support `SERIAL`; auto-incrementing integer identifiers must use `GENERATED BY DEFAULT AS IDENTITY (BIT_REVERSED_POSITIVE)`.
* **Change**:
  * `SERIAL` column definitions are converted to `BIGINT`.
  * Every transformed table automatically has a synthetic primary key prepended to its column list:
    ```sql
    spanner_pk_id BIGINT GENERATED BY DEFAULT AS IDENTITY (BIT_REVERSED_POSITIVE) PRIMARY KEY, ...
    ```
  * This prevents duplicate key conflicts when tests insert repeated row values and satisfies Spanner's primary key requirement.

### C. Remote Network Timeout Alignment (`TEST_TIMEOUT=30000`)
* **Why**: Official `node-postgres` tests assume zero-latency local socket communication (`localhost:5432`) and default to a `5000ms` timeout. Over remote network connections to Google Cloud Spanner, multi-query transactions or batch loops take longer than 5 seconds.
* **Change**: The runner sets `TEST_TIMEOUT=30000` (30 seconds) by default across all test files and helper suites (`suite.cjs` and `test-helper.cjs`), preventing false timeouts on remote network round trips.

## 4. Helper Files Overview

* **`run_pg_suite.cjs`**: Main executable test orchestrator.
* **`prepare_tables.cjs`**: Pre-processor that rewrites DDL and pre-creates test tables.
* **`cleanup_tables.cjs`**: Post-execution cleanup utility that drops test tables.
* **`created_tables.json`**: Generated manifest tracking all tables created during testing.
