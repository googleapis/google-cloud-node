# Cloud Spanner PG Suite Adaptations & Invariants

This document outlines the source, architectural adaptations, SQL dialect modifications, and directory exclusions applied when porting the official [`node-postgres` (`pg`) test suite](https://github.com/brianc/node-postgres/tree/c5e8c9a57bff6d9160ec5dbd5c4f4c1e4c460711/packages/pg/test) to execute against **Google Cloud Spanner** via `@google-cloud/spanner-driver`.

---

## 1. Upstream Source & Porting Scope

* **Upstream Reference**: [`brianc/node-postgres/packages/pg/test` (Commit: `c5e8c9a`)](https://github.com/brianc/node-postgres/tree/c5e8c9a57bff6d9160ec5dbd5c4f4c1e4c460711/packages/pg/test)
* **Ported Scope**: All integration tests for client queries, parameter binding, transactions, type parsers, and connection pooling in `integration/client/` and `integration/connection-pool/`.

### Omitted Upstream Test Suites & Directories:

| Upstream Directory / Suite | Reason for Exclusion |
| :--- | :--- |
| **`cloudflare/`** | Tests Cloudflare Workers runtime compatibility (`workerd` environment and WebSocket-based socket polyfills). Inapplicable to Node.js native gRPC / CGO drivers. |
| **`native/`** | Tests `pg-native` (Node bindings to C `libpq.so`). `@google-cloud/spanner-driver` communicates with Cloud Spanner via `@google-cloud/spannerlib-node` (Google Cloud gRPC / CGO `spannerlib`), not `libpq`. |
| **`tls/`** | Tests local TCP socket TLS handshakes, custom server certificates (`server.crt`), and mutual TLS client keys (`client.key`) with standalone PostgreSQL daemons. Cloud Spanner connections use Google Cloud IAM authentication and gRPC TLS/ALTS transport. |
| **`unit/`** | Tests internal implementation details of `node-postgres`'s pure-JS wire-protocol packet serializer/deserializer (`connection.js`, `packet-reader.js`, etc.). `@google-cloud/spanner-driver` maintains its own comprehensive TypeScript unit test suite in `test/unit/`. |

## 2. Architectural & Schema Adaptation Principles

### Primary Keys & Permanent `CREATE TABLE`
* **Upstream `node-postgres`**: Used `CREATE TEMP TABLE tableName(...)` or `CREATE TEMPORARY TABLE`.
* **Cloud Spanner Requirement**: Cloud Spanner does not support temporary or unlogged tables.
* **Adaptation**: Converted to standard `CREATE TABLE IF NOT EXISTS` with a Spanner-compatible Bit-Reversed identity primary key:
  ```sql
  CREATE TABLE IF NOT EXISTS tableName (
    spanner_pk_id BIGINT GENERATED BY DEFAULT AS IDENTITY (BIT_REVERSED_POSITIVE) PRIMARY KEY,
    -- additional columns
  )
  ```

### Asynchronous DDL Callback Chaining (`CREATE TABLE` -> `DML`)
* **Upstream `node-postgres`**: Issued unchained queries sequentially (`client.query('CREATE TABLE...')`, `client.query('INSERT...')`) over a single FIFO TCP socket connection.
* **Cloud Spanner Requirement**: Cloud Spanner processes DDL (`CREATE TABLE`) via the **Database Admin API** (`UpdateDatabaseDdl`) and DML/DQL (`INSERT`/`SELECT`) via the **Data API** (`ExecuteSql`). Schema changes take ~5-10s to propagate across Cloud Spanner database nodes on GCP.
* **Adaptation**: Chained callbacks so `CREATE TABLE` finishes on GCP before `INSERT`/`SELECT` queries are issued (`client.query('CREATE TABLE...', (err) => { client.query('INSERT...', ...); })`).

### Self-Contained Test Data Cleanup (`DELETE FROM`)
* **Upstream `node-postgres`**: Relied on temporary tables dropping automatically when TCP socket connections closed.
* **Adaptation**: Added explicit data cleanup (`DELETE FROM tableName`) before inserting test rows to prevent row accumulation across test runs.

## 3. Deleted Test Files (Raw TCP Socket Protocol)

The following test files tested low-level PostgreSQL TCP socket wire protocols that **can never apply** to Cloud Spanner's gRPC channel architecture, and were removed:

| Deleted Test File | Reason for Deletion |
| :--- | :--- |
| **`connection-timeout-tests.cjs`** | Created a local raw TCP server to test TCP socket read timeouts (`query_timeout: 1000`). Cloud Spanner communicates via gRPC / CGO channels. |
| **`ssl-tests.cjs`** | Tested raw PostgreSQL `SSLRequest` packet negotiation (`80877103`) over TCP sockets. Cloud Spanner uses Google Cloud IAM / gRPC TLS authentication. |
| **`network-partition-tests.cjs`** | Simulated TCP socket drops via local Node `net.createServer()`. Spanner uses HTTP/2 gRPC channel pools. |
| **`connection-pool/tls-tests.cjs`** | Tested PostgreSQL SSL/TLS client certificate files (`PGSSLROOTCERT`, `PGSSLCERT`, `PGSSLKEY`) over raw TCP sockets. Cloud Spanner uses Google Cloud IAM / gRPC TLS authentication. |
| **`connection-pool/native-instance-tests.cjs`** | Tested `libpq` C-binding toggles (`pg.native`). `@google-cloud/spanner-driver` uses the native `spannerlib-node` Go CGO bridge. |

*Note: Accompanying TCP packet mocking helpers (`test-buffers.cjs` and `buffer-list.cjs`) were also removed in favor of a single unified `test/pg-suite/test-helper.cjs`.*

## 6. Dynamic Database Lifecycle & Single Helper Architecture

* **Single Unified Helper (`test/pg-suite/test-helper.cjs`):**
  * Merged test runner logic (`Suite`, `Test`) directly into `test-helper.cjs`.
  * Exports `Suite`, `Client`, `pg`, `connect()`, assertions (`assert.calls`, `assert.raises`), and table fixtures (`createPersonTable`).
* **Dynamic Database Management (`test/pg-suite/run_pg_suite.cjs`):**
  * Aligned with `system-test/driver.ts` environment variable resolution (`SPANNER_INSTANCE`, `DATABASE_URL`, `SPANNER_CONNECTION_STRING`, `SPANNER_PROJECT`, `SPANNER_EMULATOR_HOST`).
  * Automatically creates a fresh temporary Spanner PostgreSQL-dialect database (`test_pg_${Date.now()}`) using the Cloud Spanner Database Admin Client.
  * Pauses 3 seconds to warm up Spanner session nodes before test execution.
  * Drops the temporary database in `finally` upon test completion.
  * Compiles and outputs master summary metrics to `test/test_results.json`.
